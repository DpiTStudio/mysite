# 📂 Полная документация файла `settings.py` (DPIT-CMS)

Этот документ содержит структурированное и подробное описание настройки проекта Django. Конфигурация разбита на логические блоки для удобства чтения и поддержки. Ниже представлен детальный разбор каждой строки и секции файла.

---

## 🏗 Основные настройки и импорты

### Библиотеки и переменные окружения (Строки 10-22)
В этом блоке подключаются необходимые библиотеки и инициализируется инструмент для работы с переменными окружения (`.env`), чтобы скрыть конфиденциальную информацию.

* **Строка 10 (`import os`)**: Импорт стандартного модуля `os` для работы с файловой системой и путями.
* **Строка 11 (`from pathlib import Path`)**: Импорт `Path` для современного и удобного управления путями в Python.
* **Строка 12 (`import environ`)**: Импорт библиотеки `django-environ` для безопасного хранения секретных данных (паролей, ключей).
* **Строка 13 (`import importlib.util`)**: Используется для проверки наличия установленных библиотек без выбрасывания ошибок (например, для проверки WhiteNoise).
* **Строки 16-18 (`env = environ.Env(...)`)**: Инициализация объекта `env`. По умолчанию устанавливается значение `DEBUG=True`, если иное не задано в окружении, и приводятся типы.
* **Строка 20 (`BASE_DIR = ...`)**: Определение корневой абсолютной директории проекта. Поднимается на два уровня вверх от текущего файла (`settings.py`).
* **Строка 22 (`environ.Env.read_env(...)`)**: Чтение файла `.env`, находящегося в корне проекта, для загрузки скрытых конфигураций.

## 🔒 Безопасность

### Защита и отладка (Строки 27-41)
Блок отвечает за общую безопасность приложения и доступы.

* **Строка 28 (`SECRET_KEY`)**: Ключ криптографической защиты (используется для подписи сессий, защиты от CSRF и т.д.). Берется из `.env`, если его там нет — используется дефолтный резервный ключ (исключительно для разработки).
* **Строка 30 (`DEBUG = env('DEBUG')`)**: Режим отладки. Если `True`, Django будет показывать подробные страницы с системными ошибками. **Необходимо отключать (`False`) на рабочем сервере (Production)**.
* **Строки 32-38 (`ALLOWED_HOSTS`)**: Список доменов и IP-адресов, по которым проект разрешает к себе обращаться. Если запрос придет на другой домен, Django его отклонит как небезопасный.
* **Строки 40-41 (`INTERNAL_IPS`)**: Если в переменной окружения заданы внутренние IP-адреса, они добавляются в список `ALLOWED_HOSTS` (полезно для Django Debug Toolbar или локального тестирования).

## 📦 Установленные приложения (INSTALLED_APPS)

### Раздел приложений (Строки 46-68)
Перечень всех активированных компонентов и модулей приложения. Порядок важен.

* **`jazzmin`**: Современная графическая тема для админ-панели. Ставится всегда первой, до `django.contrib.admin`.
* **`django.contrib.*`**: Стандартные встроенные приложения Django:
  * `admin`: Стандартная панель администратора.
  * `auth`: Система пользователей и аутентификации.
  * `contenttypes`: Система связей типов контента.
  * `sessions`: Управление сессиями браузера.
  * `messages`: Система флеш-уведомлений.
  * `staticfiles`: Подсистема управления статическими файлами (CSS/JS).
  * `sitemaps`: Генератор карты сайта (`sitemap.xml`) для поисковиков.
* **`captcha`**: Библиотека для использования капчи в форматах обратной связи.
* **Локальные приложения**: `main`, `news`, `portfolio`, `reviews`, `logfiles`, `accounts`, `tickets`, `mail`, `services`, `cart`, `knowledge_base` — кастомные приложения проекта, реализующие бизнес-логику сайта.
* **`tinymce`**: Библиотека визуального HTML-редактора текста для админки.

## ⚙ Промежуточное ПО (MIDDLEWARE)

### Обработчики запросов (Строки 73-85)
Слои, через которые последовательно проходит запрос от пользователя к серверу перед попаданием в контроллер (View).

* **Строки 73-81 (`MIDDLEWARE`)**: Стандартные обработчики:
  * `SecurityMiddleware`: Базовые настройки безопасности (переадресации, заголовки).
  * `SessionMiddleware`: Механизм поддержки независимых сессий.
  * `CommonMiddleware`: Базовая обработка пути, нормализация URL (добавление слеша).
  * `CsrfViewMiddleware`: Мощная защита от межсайтовой подделки запросов (CSRF).
  * `AuthenticationMiddleware`: Привязка текущего сеанса пользователя (Auth) к запросу (request).
  * `MessageMiddleware`: Обработка всплывающих/одноразовых уведомлений.
  * `XFrameOptionsMiddleware`: Защита от Clickjacking атак (запрет `iframe`).
* **Строки 83-85 (`HAS_WHITENOISE...`)**: Динамическая проверка, установлена ли библиотека `whitenoise`. Если она есть, её middleware автоматически вставляется на вторую позицию списка для высокопроизводительной раздачи статических файлов.

## 🌐 Маршрутизация и шаблоны

### URL‑конфигурация (Строки 90-114)

* **Строка 90 (`ROOT_URLCONF = "app.urls"`)**: Указывает на главный файл проекта, где хранятся корневые правила маршрутизации (URL) сайта.
* **Строки 92-112 (`TEMPLATES`)**: Конфигурация системы генерации HTML страницы.
  * `BACKEND`: Движок рендеринга шаблонов (`DjangoTemplates`).
  * `DIRS`: Указывает, что общие шаблоны находятся в глобальной папке `templates` в корне проекта.
  * `APP_DIRS: True`: Разрешает Django также искать файлы в папке `templates/` внутри каждого приложения.
  * `context_processors`: Специальные функции, передающие глобальные переменные сразу во все шаблоны (работа с сообщениями, корзиной, списком последних новостей, тема сайта).
* **Строка 114 (`WSGI_APPLICATION`)**: Указывает объект приложения для связи интерпретатора с веб-сервером через синхронный протокол WSGI (необходимо для запуска продакшена).

## 🔑 Валидация паролей

### Проверка надежности (Строки 132-137)
Список валидаторов, проверяющих пароль на безопасность при добавлении пользователя:
* `UserAttributeSimilarityValidator`: Пароль не должен быть похож на имя, фамилию или никнейм пользователя.
* `MinimumLengthValidator`: Контролирует минимальную длину пароля.
* `CommonPasswordValidator`: Отклонит пароль, если он слишком популярен и есть в хакерских словарях.
* `NumericPasswordValidator`: Запрещает пароли, состоящие исключительно из цифр.

## 📁 Статика и Медиа-файлы

### Настройки файлов (Строки 150-168)

* **Строка 150 (`STATIC_URL = "/static/"`)**: Префикс URL, по которому браузер запрашивает статические файлы (CSS, JS, графику сайта).
* **Строка 151 (`STATICFILES_DIRS`)**: Список директорий с исходной статикой, где Django ищет файлы в режиме разработки.
* **Строка 152 (`STATIC_ROOT`)**: Пустая директория, в которую копируется (собирается) абсолютно вся статика при команде `collectstatic` (используется только для продакшена).
* **Строка 154 (`MEDIA_URL = "/media/"`)**: Префикс URL для пользовательских, загружаемых через админку или сайт файлов (аватарки, обложки).
* **Строка 155 (`MEDIA_ROOT`)**: Физический путь на сервере к директории хранения пользовательского медиа.
* **Строки 158-168 (`STORAGES`)**: Определяет хранилища для файлов. По умолчанию используются локальные диски. Если режим отладки выключен (`DEBUG = False`), подключается `CompressedManifestStaticFilesStorage` из библиотеки `whitenoise`. Он добавляет хэши к файлам (бороться с кэшем браузера старых версий файлов) и архивирует их "на лету" (gzip).

## 🛠 Настройки Jazzmin (Админ-панель)

### Глобальный стиль админки (Строки 186-272)
Конфигурация переменной `JAZZMIN_SETTINGS` отвечает за кастомизацию интерфейса панели администратора приложения:
* Название сайта, префиксы, логотипы, приветственные надписи (`site_title`, `site_brand`, `site_logo`).
* `show_ui_builder`: Включает онлайн-конструктор тем Jazzmin в интерфейсе.
* `order_with_respect_to`: Задает строгий порядок отображения групп (приложений) в левом меню-баре.
* `icons`: Назначает уникальные красивые иконки от `FontAwesome` (например, шестеренки, конверты, графики) для каждого приложения и таблицы (модели), организуя визуальную иерархию.
* `menu`: Дополнительно настраивает левое навигационное меню, задает жесткие ссылки в интерфейсе ("Главная страница", "История действий") и выводит список всех модулей.

### Тонкие настройки UI (Строки 274-304)
Конфигурация `JAZZMIN_UI_TWEAKS` отвечает за техническое отображение темы:
* `theme`: Используется преднастроенная темная тема "darkly".
* Настройка шрифтов, компактного отображения, фиксированная левая боковая панель (`sidebar_fixed: True`) и зафиксированный "подвал".
* `button_classes`: Глобально переопределяет CSS-классы кнопок на кнопки из фреймворка Bootstrap.

## 🛡 Расширенная безопасность и CSRF

### Подготовка к Production (Строки 309-329)

* **Строки 309-318 (`CSRF_TRUSTED_ORIGINS`)**: Белый список доверенных доменов (включая порты разработки и производственные домены). Если форма придет с домена вне списка — сервер отклонит её.
* **Строки 319-322 (`CSRF/SESSION_COOKIE_...`)**: Свойства Cookie. Переменные `SECURE` включают передачу сессий строго через защищенное (HTTPS) соединение. Включаются автоматически, если `DEBUG = False`.
* **Строки 323-328 (`SECURE_SSL_REDIRECT`, `SECURE_HSTS_SECONDS...`)**: Усиленные HTTPS настройки для серверов продакшена с сертификатами. Переадресует трафик с HTTP на HTTPS.
* **Строка 329 (`X_FRAME_OPTIONS = "DENY"`)**: Полностью запрещает браузеру встраивать сайт или админку внутри тега `<iframe>` на сторонних сайтах (защита от Clickjacking).

## 📝 Логирование (LOGGING)

### Система отчетов об ошибках (Строки 334-367)
Современная и подробная настройка ведения логов (`logging` dictionary config).
* **Форматтеры**: Разные форматы вывода. Для файла — с подробным упоминанием модулей.
* **Handlers (Обработчики)**: 
  * `file`: Записывает системные логи в файл `logs/django.log` начиная с уровня `INFO`.
  * `console`: Пишет логи в окно терминала, где запущен сервер (при разработке - уровень `DEBUG`, в продакшене - только `INFO`).
  * `skip_broken_pipe`: Специальный фильтр, который убирает лишний мусор при преждевременном разрыве соединения со стороны клиента.
* **Loggers (Логгеры)**: Конфигурация перехвата логов самой системой Django и кастомным приложением `news`.

### Автоматизация логов (Строки 377-379)
* Скрипт проверяет наличие папки `logs/` на сервере/ПК и физически создает ее, если она отсутствует, чтобы система сохранения файлов не крашилась при чистом запуске.

## 📧 Почта (SMTP и IMAP)

### Настройки отправки писем (Строки 384-391)
Конфигурация для рассылок писем, уведомлений с сайта:
* Активация бэкенда SMTP от Django.
* Подключение идет к почтовому серверу провайдера (в данном случае `smtp.timeweb.ru`) через защищенный SSL-порт `465`.
* Учетные данные (`EMAIL_HOST_USER` и `EMAIL_HOST_PASSWORD`) загружаются из невидимых переменных файлов `.env`.

### Настройки получения писем (Строки 396-399)
Учетные параметры для сервисов поддержки (например, автоматическое чтение почты тикет-системой). За работу отвечает протокол IMAP (`imap.timeweb.ru`, порт `993`). Синхронизировано с едиными логинами-паролями.

## 🚀 Celery

### Асинхронные задачи (Строки 404-409)

Конфигурация менеджера фоновых задач Celery. По умолчанию связывается с сервером Redis (`redis://localhost:6379/2`).
